HP · Newsroom Migration

HP Newsroom on Edge Delivery Services

Rebuilding hp.com/us-en/newsroom on Adobe Edge Delivery Services — migrating the site chrome, importing the full newsroom archive of 1,181 articles into Document Authoring, and building the blocks that power the landing page and the faceted archive. This is the handoff playbook for Code & Theory: what we gathered, what Drago built, the decisions and assumptions behind it, and where Code & Theory takes it from here.

Project overview

This effort recreates HP's US-English Newsroom — the public home for HP press releases, blogs, and press kits — on Adobe Edge Delivery Services (EDS), authored through Document Authoring (DA). It follows an EDS block-based development model: the newsroom's chrome, articles, landing modules, and archive are all delivered as authorable blocks fed by a single content query index.

Goals

  • Recreate the HP newsroom experience on Edge Delivery Services, authored in DA.
  • Migrate the full article archive (press releases, blogs, press kits) with metadata intact.
  • Reproduce the landing page and a faceted, searchable archive driven by a query index.
  • Match HP's brand identity — typeface, color, header, and footer.

Approach

  • EDS block-based development only — every module is an authorable block.
  • A single content query index (/us-en/newsroom/query-index.json) powers all dynamic listing blocks.
  • Content bulk-imported from the public HP sitemap into DA, one page per article, each carrying an EDS Metadata block.
  • Sort and filter on an authored created-date and a topic taxonomy projected into the index.

Use case & requirements

Use case. Recreate HP's US-English Newsroom — the public hub for HP press releases, blogs, and press kits — on Edge Delivery Services, authored in Document Authoring. The experience is a landing page of curated, recent stories plus a faceted archive across the full back catalog, all reading from a single content query index.

AreaWhat we found

Content mix711 press releases · 323 blogs · 149 press kits (US-en only; ~80 other locale sitemaps exist if scope expands).

Topic taxonomyNot in page metadata — HP's newsroom embeds a JSON index of all articles and filters client-side. Topics follow a fixed 46-topic taxonomy, extracted from that embedded index.
TemplatesTwo source templates — a post-2024 template and a pre-2024 one (breakpoint data-src images, DAM paths with spaces). Editorial body lives in the c-title-and-text-v2 component.

Supporting analysis

A markup-consistency probe (12 pages across 3 templates × 2016–2026) confirmed press releases and blogs share one clean, stable template — a single importer, Phase 1 (~1,034 articles, low risk). Press kits are a heavier, interactive template (asset galleries, download modals, dropdowns) and were scoped separately. Descriptions are absent on ~1/3 of older pages, so the importer falls back to the first body paragraph.

Site chrome — header & footer Complete

The first workstream migrated the newsroom's shared chrome so every imported page renders inside HP's own navigation. The header and footer were migrated and styled using the Experience Modernization Agent (EMA) — which generated the EDS block structure and base styling from the production site — then refined by the Drago team.

  • Header — the HP mega-menu navigation, migrated via EMA and refined as an EDS block. Open menus dim and blur the page behind them; the nav collapses to a mobile menu through tablet and small-laptop widths.
  • Footer — the HP newsroom footer, migrated via EMA into an authorable block.
Header and footer shipped first (Migrate HP newsroom header and footer to EDS) so that all subsequently imported articles inherit the correct chrome.

Brand typeface — Forma DJR Complete

HP's brand typeface is Forma DJR, self-hosted on hp.com as a single face with a synthetic bold and an Arial fallback. The boilerplate EDS project shipped with Roboto; we swapped in Forma DJR so the newsroom reads as HP.

  • Added fonts/forma-djr.woff2 and .woff, removed the Roboto faces.
  • Set both --body-font-family and --heading-font-family to forma-djr, forma-djr-fallback, arial, sans-serif.
  • Arial stands in as the fallback face before Forma DJR loads — the same behavior as hp.com.

Per-page metadata captured

  • Title ← og:title
  • Description ← meta[description] / og:description, with a fallback to the article's first paragraph (~1/3 of older pages have none)
  • Image ← og:image (absolute DAM URL, sideloaded into the Media Bus on preview)
  • created-date ← HP's created-date meta, normalized to ISO YYYY-MM-DD
  • type — Press Release / Press Blog / Press Kit

Engineering notes

  • Path normalization: DA source paths use EDS-normalized slugs (lowercase, non-alphanumeric runs → single -, trimmed) — otherwise the preview 404s. ~253 older slugs needed this.
  • Two source templates: a post-2024 template and a pre-2024 one (breakpoint data-src image syntax, DAM paths with spaces) — a recursive walker handles both.
  • Image guards: images ≥ 20 MB and TIFF/GIF/SVG are excluded (some HP DAM mastheads are 48 MB TIFFs / 145 MB+ PNGs).
  • Press kits imported best-effort using existing blocks — galleries collapse into the cards block; interactive download modals and dropdowns are intentionally dropped for this pass.

Query index Complete

A single query index at /us-en/newsroom/query-index.json is the data source behind every dynamic block on the site — the landing modules and the archive all read from it.

ColumnRole
path, title, description, imageCard rendering
typeMedia Type facet — Press Release (709) / Press Blog (323) / Press Kit (149)
created-dateSort key — ISO YYYY-MM-DD
topicTopics facet — comma-separated slugs
lastModifiedEDS system field — epoch seconds
Mixed date formats. created-date is an ISO string while lastModified is epoch seconds, so every block normalizes both to epoch milliseconds via a toEpoch() helper before sorting or formatting. Blocks sort on the authored created-date — never on lastModified, which resets to migration time.

Topic taxonomy Complete

Article topics aren't in the individual page metadata on hp.com — the newsroom embeds a JSON index of every article and filters it client-side. We extracted that index, mapped each article to HP's fixed 46-topic taxonomy, and backfilled a topic metadata field onto the DA pages that carry topics.

  • 753 pages backfilled with a comma-separated list of topic slugs (e.g. financial, 3d_printing); 416 topicless articles left untouched.
  • The 46-topic list drives the Topics facet in the archive — matched by slug against each article's topic.
  • Backfill inserted a metadata row into each page's existing Metadata block and re-previewed — 753/753 succeeded, 0 failures.

Newsroom landing page Complete

The landing page is composed from a full-bleed hero on top of curated, index-driven feeds plus the faceted archive.

blockhero
Full-bleed background image with an overlaid content band — divider rules per line, scrim over the image, responsive down to mobile. Generic: any authored picture becomes the background and every remaining line renders in the band.
blocklatest-news
The newest 4 articles from the query index, sorted on created-date. Optimized images, headline, and description.
blockmore-articles
The next 6 articles after latest-news (skips the first 4), so the two feeds never repeat a story.
blockpress-kits-listing
The latest 4 press kits — filtered from the index by the /newsroom/press-kits/ path — surfaced on the landing page.
blockarticles-listing
The full faceted archive of all 1,181 articles — keyword search, Media Type and Topics facets, sort, and Load More. See Article archive.

Article archive — articles-listing Complete

The articles-listing block is the faceted archive over all 1,181 articles. It reads the query index and filters, sorts, and paginates entirely client-side.

Features

  • Card grid — 3-up on desktop; image, title, two-line description, and a Read button.
  • Keyword search across title and description.
  • Media Type facet (type) and a Topics facet over the 46-topic taxonomy.
  • Sort — Newest / Oldest (on created-date) and A–Z / Z–A.
  • Removable chips + Clear all, and a Load More that reveals the next batch of 9.
  • Mobile — single-column cards with a combined Sort & Filter modal, state synced with the desktop controls.

Only real articles appear — a path filter keeps the landing, archive, and any test pages out of the results.

Decisions & assumptions Handoff

The choices behind the build — Code & Theory should understand these before extending the work.

DecisionRationale / assumption
Sort on authored created-date, not EDS lastModifiedEDS's system lastModified resets to migration time for every page, so it can't order the archive. Blocks sort on the authored, ISO-normalized created-date.
No published-date carried from HPOnly created-date is authored/indexed for sorting; lastModified remains a system field.
Family-only font swap to Forma DJRSwap the boilerplate Roboto for HP's brand face without re-scaling the whole type ramp — lowest-risk brand match.
Hero as an explicit blockAutoblocking was removed; the masthead is an authored hero block, so authors control the eyebrow/title/date and it renders consistently.
Corporate boilerplate dropped on importEverything from an "About HP" / "Media Contact" component onward is dropped; the article's own closing paragraph is kept as real content.
Press kits imported best-effortMigrated with existing blocks (metadata, hero, body, galleries → cards); interactive download modals and dropdowns intentionally dropped for this pass.
Delivery via branch + PRAll work shipped through feature branches and PRs on AdobeDrago/hp, never pushed straight to main.
Topic values stored as slugsBackfilled a singular topic field (comma-separated slugs); created-date left unchanged during backfill.

Known limitations & accepted quirks Review

Accepted for this delivery — each is a candidate for follow-up if Code & Theory needs it resolved for production.

  • Article pages are at MVP fidelity, not a production pixel match
    Individual article pages were migrated and assembled using existing blocks to reach an MVP — they don't yet replicate the exact styling of the production newsroom. Example: a migrated 2026 press release. Matching production styling per template is a follow-up for Code & Theory.
  • created-date clustering (~87%)
    1,027 of 1,181 articles show 2024-06-18 because HP's 2024 CMS migration reset the date on older content. True editorial dates are recoverable from the embedded newsroom JSON (ad, epoch ms) but were not applied this pass.
  • Missing descriptions (~1/3 of older pages)
    Handled with a fallback to the article's first paragraph; index shows 1,165 of 1,181 with a description.
  • Press-kit interactivity dropped
    Download modals, dropdowns, and interactive asset galleries were not migrated; galleries were flattened into the cards block. Faithful press-kit experiences are a separate scope.
  • Oversized / unsupported images excluded
    Images ≥ 20 MB and TIFF/GIF/SVG are skipped (some HP DAM mastheads are 48 MB TIFFs or 145 MB+ PNGs). Affected heroes fall back to no masthead.
  • 416 articles have no topic
    Source data has no topic for those articles, so they won't match any Topics facet until tagged.
  • Topic data provenance
    The topic taxonomy was scraped from HP's public embedded JSON. Confirm this source is acceptable for production use before go-live.

Developer notes

Date normalization

Listing blocks share a toEpoch() helper: numeric values below 1e12 are treated as epoch seconds and multiplied by 1000; everything else goes through Date.parse. Sort and display both work off that normalized millisecond value.

Index as the single source

Every dynamic block (latest-news, more-articles, press-kits-listing, articles-listing) defaults to /us-en/newsroom/query-index.json, and an author can override the source with a link in the block. Change the index config once and every feed updates.

Button color gotcha

The project's global button { color: var(--background-color) } renders white — which made block buttons white-on-white. Listing blocks reset this with .articles-listing button { color: inherit }.
